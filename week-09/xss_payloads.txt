==================================================
SESSION 26: CLIENT-SIDE ATTACK PAYLOADS
==================================================

1. REFLECTED XSS
* Payload Used: [<script>alert('XSS')</script>]
* Concept: Why does this attack disappear when you refresh the page?
Answer: Reflected XSS is not stored on the server — the payload only executes when the malicious URL is visited, so refreshing with a clean URL removes it.

2. STORED XSS (Cookie Theft)
* Cookie Value Stolen: [admin_secret_99812_do_not_share]
* Payload Used: [<script>alert(document.cookie)</script>]

3. CROSS-SITE REQUEST FORGERY (CSRF)
* Malicious URL Crafted: [http://localhost:8081/transfer?to=Attacker&amount=5000]
* Concept: What is the primary defense against CSRF?
Answer: The primary defense against CSRF is using anti-CSRF tokens — unique, unpredictable values tied to the user's session that must be included in every state-changing request.
